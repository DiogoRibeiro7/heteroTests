# Development

## Setup

```bash
git clone https://github.com/DiogoRibeiro7/heteroTests
cd heteroTests
./setup.sh                      # Debian-based systems: R, renv and the dependencies
Rscript scripts/setup_helper.R  # Windows and macOS
```

The package locks its dependencies with [renv](https://rstudio.github.io/renv/);
`renv::restore()` is the manual alternative to the setup scripts. Fork the
repository and create feature branches from `main`.

## Checks

Before a pull request, run the checks CI runs:

| Command | What it enforces |
| --- | --- |
| `Rscript scripts/run_checks.R` | Styles `R/` with styler, lints it, runs the tests that read the source tree, then the whole suite once under covr, and writes a coverage report to `coverage/index.html` and the coverage itself to `coverage/coverage.rds` |
| `lintr::lint_package()` | The rules in `.lintr`: the lintr defaults with a 100-column limit |
| `spelling::spell_check_package(vignettes = TRUE)` | Spelling; accepted words live in `inst/WORDLIST` |
| `R CMD check --no-manual` | Everything `R CMD check` finds, with no unchecked warnings or notes |

Statistical tests assert behaviour: size, power, and agreement with reference
implementations such as `lmtest` and `car`, not just the structure of a
result. Add unit tests for any new functionality.

### The model-context matrix

`tests/testthat/test-model-context.R` runs the test matrix of the
[model context](design/model-context.md): about 30,000 of the suite's 41,000
expectations, and the largest part of its time. The environment variable
`HETEROTESTS_FULL_MATRIX` decides how much of it runs
(`context_full_matrix()` in `tests/testthat/helper-model-context.R`):

| `HETEROTESTS_FULL_MATRIX` | What runs |
| --- | --- |
| unset | The full matrix when `NOT_CRAN=true`, which `devtools::test()` and `testthat::test_local()` set; on CRAN, the 13 cells of `context_cran_cells` |
| `true` | The full matrix |
| `false` | The 13 CRAN cells only |

The two tests of `tests/testthat/test-cache-contract.R` that run every
resampling test at its default replications, the next largest cost, follow the
same rule. You get all of it by default. Set the variable to `false` for a
faster run, for example `HETEROTESTS_FULL_MATRIX=false Rscript scripts/run_checks.R`.

## Code

All R source lives directly in `R/`, one file per diagnostic, named after the
function it defines (`R/performBPTest.R`), with no subdirectories. Code follows
the tidyverse style guide and CRAN policies. A new test follows the
[conventions](architecture.md): it takes `(model, data, ...)`, returns an
`htest` with the fields [What every test returns](reference/test_results.md)
lists, and refuses the inputs every test refuses.

The tests that guard the public interface name every export:
`tests/testthat/test-public-api.R` lists the exports planned for 1.0.0, so a
new export fails it until it is added to the plan, and
`tests/testthat/test-return-contract.R` runs every exported test against the
documented fields, from a recipe in `tests/testthat/helper-test-recipes.R`.

## Help pages, and a warning about roxygen2

`man/` is mixed: 52 of its 133 pages are written by hand and roxygen2 generates
the rest. roxygen2 skips an `.Rd` file that lacks its `Generated by roxygen2`
header, so the hand-written pages survive a `roxygen2::roxygenise()` run, but
the run re-splits topics that the hand-written pages group on purpose
(`ht_logging.Rd` documents the whole `ht_*` logging family). Do not run it as
part of an unrelated change.

When you change a function signature, update its `.Rd` file in the same
commit: nothing regenerates a hand-written page.
`tests/testthat/test-documentation-consistency.R` runs `tools::codoc()`,
`tools::checkDocFiles()` and `tools::undoc()`, so the local test suite catches
a mismatch before CI does.

## Documentation site

This site is built with Material for MkDocs from `docs/`. Three kinds of pages
come from the package itself, and each starts with a comment that names the
script that wrote it:

| Pages | Written by | From |
| --- | --- | --- |
| The API reference, `docs/reference/`, and its part of the nav in `mkdocs.yml` | `tools/build-docs.R` | The help pages in `man/`, grouped by `tools/reference-index.R` |
| Releases and Roadmap, `docs/releases.md` and `docs/roadmap.md` | `tools/build-docs.R` | `NEWS.md` and `ROADMAP.md` |
| The user guide, `docs/guide/` | `tools/render-guides.R` | The vignettes, knitted with the package installed from the checkout |
| Redirects from the addresses of the pkgdown site, such as `docs/reference/performWhiteTest.html` and `docs/news/index.html` | `tools/build-docs.R` | The help files and their aliases, the vignettes, and a list in the script of pkgdown's other pages |

The other pages, this one included, are written by hand. A redirect is a
static HTML page that MkDocs copies as it is: the `mkdocs-redirects` plugin
takes an old address as a Markdown file, and `--strict` fails on one that ends
in `.html`.

```bash
Rscript tools/build-docs.R      # after changing man/, NEWS.md or ROADMAP.md, or adding a vignette
Rscript tools/render-guides.R   # after changing a vignette
pip install -r docs/requirements.txt
mkdocs serve                    # preview at http://127.0.0.1:8000
mkdocs build --strict           # what CI runs
```

`tools/build-docs.R` stops if a help topic is in no section of
`tools/reference-index.R`, and `tests/testthat/test-reference-index.R` checks
that every export is in one, so a new help page has to be placed in a section
on purpose. CI runs `tools/build-docs.R` again and fails if the committed pages
differ, then builds the site with `--strict`, so a broken link or a stale page
fails the build. It does not run `tools/render-guides.R`, which runs the
package's code and draws figures whose bytes differ between platforms: commit
the guide pages it writes along with the vignette that changed.

## Continuous integration

| Workflow | Runs |
| --- | --- |
| `R-CMD-check.yml` | `R CMD check`. On a pull request: Ubuntu and Windows (R release), and the hard dependencies on R 4.1. On a push to `main`, weekly and on demand, also Ubuntu (R devel and the previous release) and macOS. Weekly or on demand, `--as-cran` and reverse-dependency checks. |
| `run-checks.yml` | In parallel: `scripts/run_checks.R`, whose saved coverage is sent to Codecov; the spelling check, and a link check whose result is reported, not gated; and the quick benchmark suite. |
| `docs.yml` | Regenerates the reference, releases and roadmap pages, fails if the committed ones are out of date, builds the site with `--strict`, and deploys it to GitHub Pages from `main`. |
| `release.yml` | On a push to `main` whose `DESCRIPTION` version has no tag: builds the tarball, checks it with `R CMD check --as-cran`, tags `v<version>`, publishes a GitHub release with the tarball, and stores the tarball in `cran/`. |

A change to `Version:` in `DESCRIPTION` therefore starts a release when it
reaches `main`; leave it alone in an ordinary pull request, and add the change
to the `Development version` section at the top of `NEWS.md`.

No job runs the suite twice. Both workflows set `HETEROTESTS_FULL_MATRIX` to
`false`, except the `ubuntu-latest (R release)` job of `R-CMD-check.yml`,
which sets it to `true`: the full model-context matrix runs there, and every
other job, the coverage run included, runs the 13 CRAN cells. `R CMD check`
and covr test an installed copy of the package, where the checks that read the
source tree skip (`tests/testthat/helper-source-tree.R`); `scripts/run_checks.R`
runs the files that hold them from the source. Both workflows cancel a pull
request's earlier runs when it is pushed again, never a run on `main`.
`release.yml` sets no `HETEROTESTS_FULL_MATRIX`, so its check of the release
tarball runs the full matrix.

Every job that runs on a pull request has a `timeout-minutes` well above its
usual time, 30 minutes for an `R CMD check` job. A slow Ubuntu package mirror
can hold a job's `apt` step for more than half an hour; the timeout stops it
there, and *Re-run failed jobs* starts it again on another runner.
